# BACKLOG — план доработок инвестиционного сканера

## B-1. Резолвинг и склейка непрерывных фьючерсных рядов (высокий приоритет)
**Проблема:** в `config.yaml` сейчас используются конкретные сезонные контракты
(SiZ6, BRZ6, KCX6 и т.д.) — «быстрый вариант». MOEX ISS не отдаёт историю свечей
по переходящим тикерам вида `Si1!`, `BRENT1!` через стандартный эндпоинт
`/iss/engines/futures/markets/forts/securities/{secid}/candles.json` (пустой ответ),
а сезонные тикеры требуют ручного обновления списка при каждом ролловере (~4 раза в год).

**Что сделать:** заменить ручной учёт сезонных кодов на автоматический резолвинг
переходящих контрактов с построением непрерывного ряда:
1. В `moex_loader.py` добавить поддержку тикеров с суффиксом `!`:
   - резолвить логический корень (`BRENT1!` → активная серия `BR` по `ASSETCODE`
     из `/iss/engines/futures/markets/forts/securities.json`), выбирать контракт
     с максимальной ликвидностью (VALTODAY / открытой позицией);
   - либо загружать историю напрямую через daily-эндпоинт переходящего контракта:
     `/iss/history/engines/futures/markets/forts/securities/{secid}/daily.json`.
2. Реализовать склейку непрерывного ряда в таблице `continuous_ohlc`
   (допилить `futures_continuation.py`): рофловер за N дней до экспирации,
   корректировка цен на спред (back-adjustment), чтобы индикаторы не давали
   ложных сигналов на стыке контрактов.
3. Перевести секцию `futures` в `config.yaml` обратно на переходящие тикеры
   (`Si1!`, `BRENT1!`, `GOLD1!`, ...), убрать комментарии-подсказки про сезонность.
4. Добавить тест: на стыке двух серий нет ценового разрыва больше X% и
   дивергенции не детектируются на артефактах склейки.

**Блокировает:** полноценную автоматизацию без ручного обслуживания списка
(см. также ЭТАП 1 плана в README).
